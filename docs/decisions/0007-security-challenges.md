# 0007 — Static security challenges (phase L7)

Date: 2026-09-30 · Status: accepted

## What "safe" means here

The spec asks for "no real malware; harmless purpose-made samples only". Every challenge file is
generated by the package's own `generator.ts` from a seed: small text files, a hand-built pcap, and
source snippets. Nothing is executable malware, nothing points at real hosts (addresses come from
private and documentation ranges: 10/8, 192.0.2/24, 198.51.100/24, 203.0.113/24), and the
organisations are fictional. The lessons centre on the defence: the new editorials end with how to
fix the problem.

## Challenge set (10)

| Type             | Package                 | Skill                                                        |
| ---------------- | ----------------------- | ------------------------------------------------------------ |
| Crypto           | `caesar-intercept` (L5) | classical cipher, cribs                                      |
| Crypto           | `layered-encoding`      | recognising Base64/hex/ROT13/reversal; encoding ≠ encryption |
| Crypto           | `xor-known-plaintext`   | repeating-key XOR falls to a known header (binary file)      |
| Forensics (logs) | `auth-log-triage`       | spotting password guessing that succeeded                    |
| Forensics (pcap) | `pcap-basic-auth`       | reading HTTP Basic auth in a capture (binary file)           |
| Web analysis     | `committed-secret`      | hard-coded key in source + home-made crypto                  |
| Web analysis     | `invoice-idor`          | broken access control, confirmed from an access log          |
| Secure fix       | `fix-comment-escape`    | output encoding for HTML content and attributes (XSS)        |
| Secure fix       | `fix-upload-path`       | normalise-then-contain path checks (path traversal)          |
| Secure fix       | `fix-order-lookup-sqli` | parameterized queries (SQL injection)                        |

"Web analysis" packages use the flag format: the student reads the code, finds the bug, and proves it
by recovering the flag. The "explain" part lives in the hints and the editorial. Secure-fix packages
use the existing fix-code format, with `wrong/` solutions for the tempting half-fixes (double
escaping, prefix without `/`, stripping quotes).

All content is `review: needs-review` until the owner approves it.

## Binary challenge files

`Instance.files` values are `string | { base64 }`. The API serves base64 files as raw bytes, and the
reference solver receives the `{ base64 }` object. `fileText()` (node-only, in
`problem-kit/src/files.ts`) decodes binary files as latin1 so the "another user's flag" scan covers
them too. Generators run on a neutral platform (no `Buffer`), so packages that need Base64 carry a
small `bytes.ts` helper.

Decoy flags (for example the sessions of other staff, or rejected passwords) are random
`FORGE{…}` values from the seeded RNG. They are never another user's HMAC flag.

## Acceptance tests

- **Flag from A submitted by B is rejected and logged**: `apps/api/test/workspace.test.ts`
  (`flag.shared_suspected` audit entry; the flag itself is never stored).
- **No file contains another user's flag**: the validator checks every flag package across 50 seeds,
  and the API test now generates the files of 15 users for **every** flag problem and scans them
  (binary files included).

## Rules page

`/security/rules` states the rule "only attack Forge's own challenge files, never real systems",
what is allowed, flag-sharing consequences and how to report a real vulnerability. It is linked from
every challenge statement and from the flag panel. The reporting address comes from
`SECURITY_CONTACT_EMAIL`, since the address is the operator's decision.

## Fixed along the way

- **SQL sandbox OOM on long suites.** `/tmp` is a tmpfs that counts against the container's memory
  limit, and each test's database stayed there until the end, so after ~20 tests PostgreSQL was
  OOM-killed (`connection to server was lost`). The harness now drops each database after emitting
  its result. Covered by a 40-test regression case in `apps/runner/test/verdicts.test.ts`.
- Markdown links no longer accept protocol-relative URLs (`//host`).
- `pnpm problems:validate` runs `node dist/cli.js` (the package's own bin was not linked).
- The Playwright config loads the root `.env` for local runs.
